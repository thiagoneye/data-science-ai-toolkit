# Python development standards

- Prefer Python 3.11+ when compatible with project requirements.
- Use type hints for public functions and descriptive docstrings in English.
- Keep I/O, transformations and modeling separate; avoid opaque notebooks as sole source of truth.
- Prefer pathlib, logging, dataclasses, and configuration files over hard-coded constants.
- Run Ruff and pytest when available; explain skipped checks.
- Keep identifiers and docstrings in English, explanatory comments in Portuguese.
